Kokoro-82M Voice Cloning

Adaptive Convex Mixture Search & Broadcasted Perturbation Optimization

Key Architectural Discovery

During source analysis of the Kokoro pipeline, we identified a critical architectural constraint in KPipeline.infer: the pipeline selects exactly one row from the 510×1×256 style tensor using the phoneme length of the input sentence:

return model(ps, pack[len(ps)-1], speed, return_output=True)

This means a standard single-sentence search only optimizes one specific row. Held-out sentences of different lengths index completely different, unoptimized rows — causing severe generalization failure. Our strategy directly addresses this with a 5-sentence evaluation suite and a shared 256-dim perturbation vector applied to all 510 rows simultaneously.

Two-Phase Search Algorithm

Phase 1 — Convex Blend Weight Search (100 iterations)

Ranked all 54 stock voice tensors by cosine similarity to the target speaker. Selected top 5: af_sarah, bf_emma, af_sky, bf_lily, af_nova. Random-walked over the weight simplex (weights sum to 1), accepting new mixtures that improve the average cosine similarity on the evaluation suite. Since stock voices contain a natural, professionally-recorded row-to-row correlation, any convex combination preserves natural speech dynamics.

Phase 2 — Broadcasted 256-D Perturbation (80 iterations, annealed)

Starting from the optimal blend, we searched for a shared 256-dimensional perturbation vector δ added uniformly to all 510 rows. Elements were hard-clamped to [-0.05, 0.05] — exactly 1/3 of the stock voice standard deviation — guaranteeing naturalness without any soft penalty that would block improvement. Step size was annealed from 0.02 → 0.01 over iterations.

The fitness function is the average Resemblyzer cosine similarity between synthesized audio and the target speaker's real recordings across 5 evaluation sentences of varying lengths.

Key Findings & Analysis

  • Kokoro's row-selection mechanism makes single-sentence search dangerously overfit; a diverse multi-length evaluation suite is mandatory.
  • The convex blend search definitively beat the naive 50/50 baseline by +0.0186 while preserving completely natural, artifact-free speech.
  • Soft L2 regularization with coefficient 0.05 was too aggressive — it deducted more than a typical single-step improvement, causing zero accepted steps in Phase 2.
  • Hard clamping to ±0.05 resolved the acceptance problem and allowed Phase 2 to find improvements (+0.0291 on 3-sentence avg), but over-optimization shifted the voice toward unintended accent regions.
  • The Hindi G2P pipeline (lang_code='h') was verified to produce Indian English accent phoneme mappings, consistent with the target speaker.
  • The similarity plateau is fundamentally bounded by the frozen Kokoro-82M generator's training distribution, which contains no native Indian English data.
  • Listening checks confirmed the final submitted voice.pt is completely clean, intelligible, and definitively closer to the target speaker's timbre than the baseline blend.
